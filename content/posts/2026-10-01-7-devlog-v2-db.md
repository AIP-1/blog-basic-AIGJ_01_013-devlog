첫 버전을 만들고 보니 목표가 바뀌었다. 과제 제출용 블로그가 아니라 **AI응용프로젝트 수업 기간 동안 배운 것을 날짜별로 쌓아 가는 아카이브**를 만들고 싶어졌다.

## 요구사항 정리

1. 수업 내용, 자습 내용, 프로젝트 진행 기록을 구분한다.
2. **날짜별**로 정리되고, 수업일은 **Day N**으로 표시한다.
3. 데이터는 **데이터베이스**로 관리한다.
4. GitHub Pages에 올려서 누구나 볼 수 있어야 한다. → 서버를 쓸 수 없다.

## 테이블 설계 (ERD)

```text
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│  sessions    │      │  post_types  │      │  projects    │
│──────────────│      │──────────────│      │──────────────│
│ id (PK)      │      │ id (PK)      │      │ id (PK)      │
│ day_no  (UQ) │      │ code    (UQ) │      │ slug    (UQ) │
│ date    (UQ) │      │ name    (UQ) │      │ name         │
│ title        │      │ color        │      │ description  │
│ summary      │      └──────┬───────┘      │ repo_url     │
└──────┬───────┘             │ 1            │ started_on   │
       │ 1                   │              └──────┬───────┘
       │       N ┌───────────▼──────────┐ N        │ 1
       └────────▶│  posts               │◀─────────┘
                 │──────────────────────│
                 │ id (PK)              │
                 │ slug (UQ)            │
                 │ title, summary       │
                 │ content_md           │
                 │ date, seq  (UQ 묶음) │
                 │ type_id    (FK, 필수)│
                 │ session_id (FK, 선택)│
                 │ project_id (FK, 선택)│
                 └──────────────────────┘
```

### 설계하면서 고민한 것

- **글 유형을 별도 테이블로 뺀 이유** : `posts`에 '수업' 같은 글자를 직접 넣으면 오타가 생겨도 막을 수 없다. 코드 테이블로 분리하고 FK로 연결하면 정해진 값만 들어간다.
- **`session_id`를 NULL 허용으로 둔 이유** : 주말에 혼자 공부한 글은 수업 회차가 없다.
- **`(date, seq)` 묶음 UNIQUE** : 하루에 여러 글을 쓸 때 순서를 보장한다.
- **뷰 `v_posts`** : 화면에서 매번 4개 테이블을 조인하지 않도록 미리 묶어 두었다.

## 데이터 흐름

```text
content/posts/2026-10-01-7-devlog-v2-db.md   ← 마크다운으로 글 작성
content/sessions.csv, projects.csv           ← 회차 / 프로젝트 정보
        │
        ▼  python3 scripts/build_db.py
db/blog.db  (SQLite)
        │
        ▼  sql.js (WebAssembly로 브라우저에서 SQLite 실행)
SELECT * FROM v_posts WHERE date = '2026-10-01' ORDER BY seq;
```

서버 없이도 브라우저가 DB 파일을 받아서 **진짜 SQL**로 조회한다.

## 화면에서 쓰는 쿼리 예시

날짜별 타임라인:

```sql
SELECT date, day_no, session_title, COUNT(*) AS posts
FROM v_posts
GROUP BY date
ORDER BY date DESC;
```

유형별 글 수 (사이드바):

```sql
SELECT t.name, t.color, COUNT(p.id) AS cnt
FROM post_types t
LEFT JOIN posts p ON p.type_id = t.id
GROUP BY t.id;
```

> 블로그의 **DB** 메뉴에서 직접 SQL을 실행해 볼 수 있다.
