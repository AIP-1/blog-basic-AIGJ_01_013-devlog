ERD 과제(10/9 제출)는 **직접 그려 보라**고 하셔서, Claude에게는 그림이 아니라 방향만 물어보면서 ERDCloud로 그렸다. 실제 테이블 정의(`src/db/schema.ts`)를 보고 하나씩 옮겼다.

## 컬럼 칸 채우기

| 칸 | 뜻 | 예 |
|---|---|---|
| 논리 이름 | 사람이 읽는 이름 | 회원 ID |
| 물리 이름 | DB의 실제 컬럼 이름 | `id` |
| Domain | 같은 성격의 값을 묶는 이름표 | ID, 일시, 여부 |
| Type | 저장 형식 | `TEXT`, `TIMESTAMPTZ` |

Domain은 테이블마다 같은 이름표(예: 모든 `created_at`은 "일시")를 다시 쓰는 게 핵심이다.

## 키

- **PK**는 열쇠 표시, **UNIQUE**는 키가 아니라 제약조건이라 코멘트에 적는다.
- 회원 테이블에 `id`와 `username`(아이디)이 둘 다 있는 이유
  - `id`: 시스템이 만든 **대리 키**. 절대 안 바뀌고 비지 않는다 → PK, 다른 테이블이 가리킨다
  - `username`: 사람이 정한 **자연 키**. 소셜 로그인 회원은 비어 있고 바뀔 수도 있다 → UNIQUE만
- 닉네임은 `users`가 아니라 `profiles`에 있다. `users`는 로그인용, `profiles`는 게임·블로그용이고, 온보딩을 마쳐야 생긴다.
- FK 이름은 "단수형 + `_id`"(`user_id` → `users.id`). 역할이 있으면 역할 이름(`owner_id`, `author_id`, `follower_id`).

## 식별 / 비식별

| | 식별 (실선) | 비식별 (점선) |
|---|---|---|
| 부모 키가 자식에서 | PK의 일부 | 일반 컬럼 |
| 예 | 공감 (`post_id`, `user_id`), 출석 (`user_id`, `date`) | 댓글, 글, 세션 |

가장 와닿은 질문은 "**왜 댓글은 비식별인데 공감은 식별이야?**"였다.

- 한 사람이 한 글에 **댓글은 여러 개** 쓸 수 있다 → (글, 회원)으로 한 줄을 특정할 수 없다 → 댓글마다 `id`가 필요하다 → 비식별
- **공감은 한 번만** 할 수 있다 → (글, 회원)이 곧 그 공감이다 → 이 조합이 PK → 식별

PK를 이렇게 잡으면 "한 번만 공감"이 DB에서 자동으로 지켜진다. NULL을 허용하는 FK(답글의 부모 댓글, 카테고리 없는 글)는 PK에 들어갈 수 없어서 항상 비식별이다.

## 개수 기호

관계선 하나의 **양쪽 끝**에 기호가 하나씩 붙는다. 자식 쪽은 "부모 하나에 자식이 몇 개?"로 고른다.

- 회원 → 프로필: 온보딩 전 0, 후 1 → **Zero or One**
- 블로그 → 글: **Zero or Many**
- Zero or One or Many는 Zero or Many와 뜻이 같아서, 한쪽으로 통일했다.

## ERDCloud에서 막혔던 것

- **FK는 직접 체크하지 않는다.** 관계선을 그으면 부모 PK가 자동으로 들어온다. 그래서 FK 컬럼을 손으로 지우면 관계선까지 같이 지워진다.
- **같은 컬럼을 두 관계가 같이 쓰는 복합 FK**(프로필의 장착 캐릭터 = 내가 가진 아이템만)는 도구가 `user_id`를 두 번 만들어 버렸다. 선은 단순하게 긋고 실제 규칙은 코멘트로 적었다.
- 회원 → 이웃(follows)처럼 **같은 두 테이블 사이 관계 두 개**는 선 하나로 합쳐져 보였다. 코멘트로 역할을 구분했다.
- 카테고리 → 글을 이었더니 `blog_id`까지 따라왔다. 블로그 → 카테고리를 **식별 관계로 잘못 그어서** `blog_id`가 PK가 돼 있었기 때문이다. 비식별로 바꾸니 해결됐다.

## 검사

ERDCloud에서 SQL·TypeScript로 내보내 실제 DB와 비교했다. 처음엔 NULL 허용이 반대로 된 곳이 20곳 가까이 있었다. 특히 `comments.deleted_at`이 NOT NULL이면 "모든 댓글이 삭제된 상태"라는 뜻이 되어 버린다. 지금은 17개 테이블이 실제 DB와 일치하고, 농장·방문자 수 등 5개 테이블은 내일 추가한다.
