소셜 로그인은 개발자 센터에서 키를 받아야 쓸 수 있다. 그 전에도 누구나 가입할 수 있도록 **사이트 자체 회원가입**을 만들었다.

## 아이디로 가입하기

로그인 라이브러리(Better Auth)의 **username 플러그인**을 썼다.

- 아이디: 영문 소문자·숫자·`_`, 4~20자 (대문자로 적어도 소문자로 저장)
- 비밀번호: 8~64자, DB에는 **해시**로만 저장
- 가입하면 바로 로그인되고 온보딩(닉네임·블로그·캐릭터)으로 이동

라이브러리는 이메일을 꼭 요구해서, 아이디로만 가입하면 이메일 자리에 `아이디@users.blogville.invalid` 같은 **실제로 쓰지 않는 주소**를 넣었다. `.invalid`는 절대 실제 메일 주소가 될 수 없게 예약된 도메인이다.

```text
users     : username, role(user/admin)
accounts  : provider_id = 'credential', password = 해시
```

로그인 실패 문구는 "없는 아이디"와 "틀린 비밀번호"를 구분하지 않고 **"아이디 또는 비밀번호가 맞지 않아요"** 하나로 통일했다. 어떤 아이디가 가입되어 있는지 알려주지 않기 위해서다.

## 관리자 계정

- `users.role = 'admin'`인 사람만 관리자. **가입 요청으로는 role을 정할 수 없게** 했다 (`input: false`)
- 실제로 가입 요청에 `"role": "admin"`을 넣어 보내 봤더니 무시되고 일반 회원으로 가입됐다.
- 관리자 계정은 스크립트(`npm run admin:create`)로 만든다. 아이디·비밀번호는 코드가 아니라 `.env.local`(Git에 올리지 않는 파일)에서 읽는다.
- 관리자 페이지(`/admin`): 통계 6개, 최근 가입 20명, 최근 30일 글 30개와 삭제 버튼
- 일반 회원이 `/admin`에 들어가면 **404**. 관리자 페이지가 있다는 것조차 숨긴다.

## 테스트 13개

Playwright로 회원가입·로그인·권한을 확인했다.

```text
✅ 회원가입 후 온보딩으로 이동      ✅ 중복 아이디 거부
✅ 비밀번호 확인 불일치 거부        ✅ 틀린 비밀번호 거부
✅ 맞는 비밀번호로 로그인           ✅ 온보딩 전 회원 /admin 차단
✅ 일반 회원 /admin → 404          ✅ 일반 회원 헤더에 관리자 버튼 없음
✅ 관리자 로그인 → 광장             ✅ 헤더에 관리자 배지
✅ 관리자 페이지 열림               ✅ 콘솔 오류 없음 (×2)
```

## 트러블슈팅

### 1. 테스트가 "실패"했는데 앱은 정상

"일반 회원 /admin 접근 차단" 테스트가 실패했다. 알고 보니 그 회원이 **온보딩 전**이라 `/admin` 대신 온보딩 화면으로 보내졌고, 테스트는 404만 "차단"으로 인정하고 있었다. 테스트 기준을 "관리자 화면이 안 보이면 차단"으로 고치고, 온보딩까지 마친 회원으로도 따로 확인했다. **테스트가 틀릴 수도 있다**는 걸 배웠다.

### 2. 비밀번호를 코드에 안 남기려다 테스트 파일에 남김

관리자 비밀번호를 `.env.local`에만 두기로 해 놓고, 정작 **E2E 테스트 파일에 비밀번호를 그대로 적은 채 push**했다. 바로 테스트도 `.env.local`에서 읽게 고쳤지만, **Git 커밋 기록에는 남아 있다.** 저장소가 비공개라 지금 당장 위험하진 않지만, 공개하거나 배포하기 전에는 비밀번호를 바꿔야 한다.

> push 전에 `git grep 비밀번호` 같은 검색으로 한 번 더 확인하는 습관을 들이자.
