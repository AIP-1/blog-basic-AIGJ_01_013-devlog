Next.js 프로젝트를 만들었더니 `AGENTS.md`라는 파일이 같이 생겼다.

> This is NOT the Next.js you know. 이 버전은 학습 데이터와 다를 수 있으니 `node_modules/next/dist/docs/`를 먼저 읽어라.

AI 도구에게 주는 안내였다. 실제로 문서를 읽어 보니 바뀐 게 많았다.

## 1. 주소 값은 기다려서(await) 꺼낸다

```tsx
export default async function Page(props: PageProps<"/blog/[slug]">) {
  const { slug } = await props.params;          // 예전엔 바로 props.params.slug
  const { page } = await props.searchParams;
}
```

`cookies()`, `headers()`도 마찬가지로 `await` 해야 한다.

## 2. `middleware.ts` → `proxy.ts`

모든 요청 앞에서 실행되는 파일의 이름이 바뀌었다.

## 3. `@`로 시작하는 폴더는 특별하다

블로그 주소를 `/@닉네임`으로 하고 싶었는데, `app/@slug` 폴더는 **parallel route**라는 기능으로 인식되어 주소가 되지 않는다. 그래서 실제 페이지는 `/blog/[slug]`에 두고 **rewrite**로 주소만 바꿔 보여줬다.

```ts
async rewrites() {
  return [{ source: "/@:slug", destination: "/blog/:slug" }];
}
```

## 4. 서버 컴포넌트와 Server Action

- **서버 컴포넌트**: 기본값. 서버에서 실행돼서 **DB를 바로 조회**할 수 있다. 브라우저로는 결과 HTML만 간다.
- **클라이언트 컴포넌트**: 파일 맨 위에 `"use client"`. 버튼 클릭, 입력처럼 브라우저에서 반응해야 하는 부분.
- **Server Action**: `"use server"` 함수. 폼에서 바로 호출하면 서버에서 실행된다. API 주소를 따로 만들 필요가 없다.

```tsx
"use server";
export async function attend() {
  const viewer = await requireMember();   // 누가 눌렀는지 서버에서 다시 확인
  // ... DB에 출석 기록
}
```

Server Action은 누구나 직접 호출할 수 있는 주소처럼 동작하기 때문에, **함수마다 로그인과 권한을 다시 확인**해야 한다.

## 5. 인증 검사는 레이아웃이 아니라 페이지마다

레이아웃은 페이지를 이동해도 다시 실행되지 않는다. 그래서 공식 문서도 권한 검사를 레이아웃에 두지 말고 각 페이지와 Server Action에서 하라고 한다. 이것 때문에 헤더 코인이 안 바뀌는 문제도 겪었다. ([Blogville #3](#/post/blogville-build))

## 배운 점

- 라이브러리는 **설치된 버전의 문서**를 먼저 본다. 검색 결과나 기억은 옛날 버전일 수 있다.
- Phaser도 4 버전에서 바뀐 점을 정리한 마이그레이션 가이드와 AI용 `skills` 문서가 패키지 안에 들어 있었다.
