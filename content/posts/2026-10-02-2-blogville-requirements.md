코드보다 **요구사항 명세서**를 먼저 썼다. 무엇을 만들지 정해 두지 않으면 기능을 계속 붙이다가 방향을 잃기 쉽다.

## 사용자 흐름

```text
소셜 로그인 → (처음이면) 온보딩: 닉네임 · 블로그 주소 · 기본 캐릭터
     ↓
중앙 광장 ─┬─ 🏠 내 집 → 내 블로그
          ├─ 🏘 이웃집 → 다른 사람 블로그
          ├─ 📮 우체통 → 출석 보상
          ├─ 🏪 상점 → 캐릭터·배경 구매
          └─ 📋 게시판 → 마을 최신 글
```

## MoSCoW 우선순위

기능마다 ID(AUTH-01, POST-01 …)를 붙이고 우선순위를 매겼다.

| 우선순위 | 뜻 | 예시 |
|---|---|---|
| **M**ust | 없으면 서비스가 안 됨 | 소셜 로그인, 글쓰기, 댓글, 공감, 장착 |
| **S**hould | 있어야 기획 의도가 삶 | 경험치·레벨, 코인, 출석, 상점, 이웃 |
| **C**ould | 여유 있으면 | 이미지 첨부, 가구 배치, 답글 |
| **W**on't | 이번엔 안 함 | 실시간 멀티플레이, 유료 결제 |

### 게임이 글쓰기를 돕게

보상이 **블로그 활동**에서 나오게 했다. 그리고 보상만 노리는 반복을 막으려고 **하루 상한**을 뒀다.

| 활동 | 경험치 | 코인 | 하루 상한 |
|---|---|---|---|
| 출석 | 10 | 20 (7일 연속 +50) | 1회 |
| 글 작성 (공개, 100자 이상) | 30 | 30 | 3회 |
| 댓글 (남의 글에) | 5 | 5 | 10회 |
| 공감 받음 | 2 | 2 | 20회 |

## 기술 스택과 고른 이유

| 역할 | 선택 | 이유 |
|---|---|---|
| 언어 | TypeScript | 브라우저는 JS만 실행한다. 서버도 같은 언어로 쓰면 혼자서 두 언어를 오갈 필요가 없다 |
| 프레임워크 | Next.js 16 | 화면과 서버를 한 프로젝트에 두는 **풀스택(통짜)** 방식. 저장소와 배포가 하나 |
| DB | PostgreSQL | 회원·글·보상이 서로 얽힌 관계형 데이터. 여러 사람이 동시에 쓰는 서비스라 파일 하나짜리 SQLite 대신 서버용 DB |
| ORM | Drizzle | 테이블 정의가 SQL과 거의 같아서 ERD를 코드로 옮기기 쉽고, 마이그레이션이 **SQL 파일**로 남는다 |
| 로그인 | Better Auth | 네이버·카카오·구글을 기본 지원하는 안정 버전 |
| 에디터 | Tiptap | Tistory처럼 버튼으로 꾸미는 에디터 |
| 광장 | Phaser | 2D 게임 엔진. **아이소메트릭(2.5D) 타일맵도 지원**해서 엔진을 바꾸지 않고 업그레이드할 수 있다 |

### 고르지 않은 것

- **React + FastAPI(Python)**: AI 기능엔 좋지만 두 언어, 두 번 배포, 소셜 로그인 직접 구현까지 혼자 10일엔 부담.
- **Spring(Java)**: 실무에서 많이 쓰지만 설정이 많다.
- **Prisma, Auth.js**: 둘 다 유명하지만 확인해 보니 최신 버전이 각각 RC와 베타였다. 라이브러리를 고를 때는 **지금 안정 버전이 무엇인지** 직접 확인해야 한다는 걸 배웠다.

```bash
curl -s https://registry.npmjs.org/-/package/next-auth/dist-tags
# {"latest":"4.24.15","beta":"5.0.0-beta.32", ...}
```
