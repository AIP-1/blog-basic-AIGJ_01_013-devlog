요구사항 명세서를 상세화하던 중에 피드백을 받았다.

## 피드백

> 이미 구현되어 있는 것들도, 예를 들면 **한 페이지에 몇 개 보여주는지**, **구현 혹은 구동 방식은 어떻게 할 건지** 다 요구사항 명세서에 작성하라.

## 내가 이해한 것

지금까지 명세서에는 "글 목록은 최신순, 페이지 단위로 보여준다"처럼 **무엇을 하는가**만 있었다. 그런데 이 문장만으로는

- 한 페이지에 몇 개인지
- 요약은 몇 글자에서 자르는지
- 페이지 번호는 몇 개까지 보여주는지
- 이 기능이 서버에서 도는지 브라우저에서 도는지, 어떤 테이블을 쓰는지

를 알 수 없다. 팀원마다 다르게 이해하면 같은 기능을 다르게 만들게 된다.

## 그래서 바꾼 것

명세서 작성 양식에 두 칸을 추가했다.

| 칸 | 적는 것 |
|---|---|
| **표시 규칙** | 개수, 정렬, 페이지 나누기, 자르는 길이, 빈 화면 문구, 날짜 형식 |
| **구현 방식** | 화면(서버/클라이언트 컴포넌트), 처리(Server Action), 데이터(테이블·쿼리), 무결성(트랜잭션·잠금·제약), 검증 위치, 처리 후 화면 갱신 |

이미 구현된 기능은 **코드의 실제 값**을 그대로 옮겨 적었다. 예를 들면 글 목록은 이렇게 된다.

> 한 페이지 **8개**, 최신순(작성 시각 → 같으면 글 ID 큰 순). 요약은 본문 앞 **160자**를 **2줄**까지. 페이지 번호는 첫·끝 페이지와 현재 페이지 **앞뒤 2개**, 사이가 비면 `…`.
