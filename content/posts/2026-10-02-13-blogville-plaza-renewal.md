오늘 마지막 작업은 **광장을 "진짜 게임처럼" 만드는 것**이었다. 아이소메트릭(2.5D)이 만들어지기 전까지 쓸 2D 광장을 예쁘게 다듬고, 광장이 사이트의 중심이 되도록 구조를 바꿨다.

## 1. 그림을 코드로 그리기 (SVG)

지금까지 캐릭터는 이모지(🐱), 배경은 CSS 그라데이션이었다. 외부 그림을 가져오면 라이선스를 확인해야 해서, **그림을 코드(SVG)로 직접 그렸다**.

| 파일 | 내용 |
|---|---|
| `src/lib/art/characters.ts` | 캐릭터 11종. 같은 2등신 몸통에 귀·꼬리·머리만 다르게 |
| `src/lib/art/backgrounds.ts` | 배경 6종 (초원, 바닷가, 눈 마을, 벚꽃길, 밤의 도시, 우주) |
| `src/lib/art/town.ts` | 광장 건물: 집, 게시판, 상점, 분수, 나무, 가로등, 농장 |

- **게시판**: 왼쪽 코르크판은 마을 소식, 오른쪽은 출석 도장판. 우체통을 없애고 출석 체크를 게시판에 합쳤다.
- **상점**: 빨강·흰 줄무늬 차양, 코인 간판, OPEN 팻말
- **집**: `HOUSE_STAGES`로 단계별 성장 구조만 만들고 지금은 1단계 "작은 오두막". 지붕 색은 주인이 고른 배경 색을 따라가고, 문 옆에 주인 캐릭터가 서 있다.
- 블로그 상단처럼 넓은 칸은 배경을 늘리면 흐려져서, **넓은 칸용(760)과 좁은 칸용(320)을 따로** 그렸다.

> DB에는 그림 이름표(`asset_key`)만 있고 실제 모양은 코드에 있다. 그래서 그림을 통째로 바꿔도 DB는 건드리지 않았다.

## 2. "광장이 메인"이라는 결정

헤더에 [마을 소식] [상점] [꾸미기] 같은 메뉴가 있으면 광장을 걸어 다닐 이유가 없어진다. 그래서:

- 헤더의 이동 메뉴와 광장 아래 바로가기 카드를 **모두 없앴다**. 건물에는 걸어가서만 들어간다.
- 대신 광장이 아닌 화면에는 헤더에 **`← 광장으로 나가기`** 버튼을 넣었다.
- 광장은 **전체 화면**으로 바꾸고, 이웃집 목록·조작 안내·환영 문구는 게임 위에 띄웠다.
- 이웃집 목록은 남겼다. 나중에 즐겨찾기한 집만 광장에 보이게 할 예정이라, 나머지 블로그는 목록에서 들어가야 하기 때문이다. 검색은 내 집(내 블로그) 안에서 하기로 정했다.

이 결정에는 대가도 있었다. 요구사항 NF-17("게임을 쓰기 어려운 사람도 일반 링크로 모든 기능에 갈 수 있다")을 지금은 못 지킨다. 그래서 상태를 ⬜로 바꾸고 팀 회의 안건으로 남겼다.

## 3. 동물 농장 자리와 남/여 캐릭터

앞으로는 **동물 농장에서 동물을 키워 경험치를 얻고 레벨업**하는 방향으로 간다.

- 원래 우체통 자리에 울타리, 헛간, "🚧 준비 중" 간판이 있는 농장 **틀만** 만들었다. 들어가면 공사 중 화면이 나온다.
- 가입할 때는 **남자 주민 / 여자 주민** 중 하나만 고르고, 고른 캐릭터만 받는다.
- 원래 기본 캐릭터였던 모험가·고양이·강아지는 상점에서 판다.

## 4. 테스트로 확인하기

- 캐릭터를 방향키로 움직이는 스크린샷을 찍으려는데, 헤드리스 브라우저에서는 **1초 눌러도 거의 안 움직였다**. 화면이 느리게 그려지면서 게임 속 시간도 느려진 것이다. 키를 훨씬 오래 누르게 해서 게시판 앞까지 걸어가게 했다.
- E2E에 "헤더에 이동 메뉴가 없다", "게시판·출석·상점·농장에서 나가기를 누르면 광장으로 돌아온다" 검사를 추가했다.
- 기본 캐릭터가 바뀌자 기존 테스트가 "고양이" 카드를 못 찾아 실패했다. 테스트도 기능과 함께 고쳐야 한다.

## 5. PR 9개 머지와 충돌 정리

팀원 PR이 쌓여서 한 번에 정리했다.

| PR | 내용 |
|---|---|
| #24, #25 | 글쓰기 오류 뒤 입력값 유지, 빈 본문 안내 문구 (창근) |
| #26, #27, #28 | 태그 300자 한국어 안내, `%` 태그 페이지 오류, 이웃 추가 검증 (창근) |
| #14, #29 | BLOG·POST·SOC 상세 명세, POST-01 수정 반영 (창근) |
| #12 | GAME·SHOP·TOWN 결정 (지원) |
| #13, #15 | 광장 그림, 광장 중심 구조 (나) |

#24는 경계 상황(같은 카테고리로 두 번 연속 오류, 고친 뒤 발행, 수정 화면)까지 직접 돌려 보고 승인했다.

**같은 문서를 여러 명이 고치면 충돌이 난다.** 요구사항 문서를 4개 PR이 동시에 고쳐서:

- 변경 이력 번호가 겹쳤다 (0.8이 두 개) → 머지 순서대로 0.8 → 0.9 → 1.0 → 1.1로 이어 붙였다.
- 요구사항 ID가 겹쳤다 (TOWN-07이 "지붕 색"과 "농장" 두 개) → 먼저 결정된 쪽을 살리고 농장을 **TOWN-09**로 옮겼다.

### 실수: base 브랜치를 지웠더니 PR이 닫혔다

#15는 #13 브랜치 위에 쌓은 PR(base = `feat/town-art`)이었다. #13을 머지하면서 브랜치를 지우자 **#15가 자동으로 닫혔다**. 닫힌 PR은 base를 바꿀 수 없어서, 지운 브랜치를 커밋 번호로 되살린 뒤 PR을 다시 열고 base를 `main`으로 바꿨다.

```bash
git push origin 1199bfd:refs/heads/feat/town-art   # 지운 브랜치 되살리기
gh pr reopen 15
gh pr edit 15 --base main
```

> 쌓인 PR(stacked PR)을 머지할 때는 **위쪽 PR의 base를 먼저 main으로 바꾸고** 아래 PR의 브랜치를 지워야 한다.

## 팀원이 사이트를 보는 방법

아직 배포하지 않아서 내 컴퓨터의 `localhost:3000`에는 팀원이 들어올 수 없다. 각자 컴퓨터에서 실행한다.

```bash
git clone https://github.com/ehgo508/blogville.git
cd blogville
npm install
createdb blogville
cp .env.example .env.local   # DATABASE_URL, BETTER_AUTH_SECRET 채우기
npm run db:migrate
npm run db:seed              # 아이템이 바뀌면 다시 실행
npm run dev                  # http://localhost:3000
```

배포(Vercel + Neon)는 나중에 하기로 했다.
