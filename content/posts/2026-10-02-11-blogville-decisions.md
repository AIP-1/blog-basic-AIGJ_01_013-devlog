팀원이 요구사항의 열린 질문 8개에 결정을 내렸고, 그중 구현이 필요한 것을 만들었다.

| 요구사항 | 결정 | 구현 |
|---|---|---|
| GAME-01 | 기본 캐릭터를 1종이 아니라 **3종 모두** 준다 | 온보딩 수정 + 기존 회원 데이터 마이그레이션 |

## 1. 이미 가입한 회원의 데이터는? → 데이터 마이그레이션

"가입할 때 3종을 준다"는 코드만 바꾸면 **이미 가입한 사람**은 여전히 1종뿐이다. 그래서 테이블 구조가 아니라 **데이터를 바꾸는 마이그레이션**을 만들었다.

```sql
INSERT INTO user_items (user_id, item_id)
SELECT p.user_id, i.id
FROM profiles p CROSS JOIN items i
WHERE i.type = 'character' AND i.is_starter = true
ON CONFLICT (user_id, item_id) DO NOTHING;   -- 이미 있으면 건너뜀
```

마이그레이션 파일로 남겨야 팀원 각자의 DB와 나중에 배포할 DB에도 똑같이 적용된다. 실행해 보니 기존 회원 2명이 1종 → 3종이 됐다.

## 2. 연속 출석 버그: "이번 달"이 아니라 "가장 최근 1건"

출석 화면은 달력을 그리려고 **이번 달 출석 기록만** 읽었는데, 연속 일수도 거기서 꺼내고 있었다. 그래서 9/30에 출석하고 10/1에 열면 이번 달 기록이 없어서 0일이 됐다.

```ts
// 마지막 출석이 오늘이나 어제면 이어지는 중, 그보다 오래됐으면 끊김
export function currentStreak(last, today) {
  if (!last) return 0;
  return last.date === today || last.date === previousDay(today) ? last.streak : 0;
}
```

경계 상황을 테스트로 남겼다: 달 바뀜(9/30 → 10/1), 해 바뀜(12/31 → 1/1), 그저께가 마지막(끊김).

## 3. 오류가 나도 오류 화면 대신 안내

꾸미기에서 장착할 때 서버가 오류를 던지면 화면 전체가 오류 페이지로 바뀌었다 (팀원이 리뷰에서 찾았다). `try/catch`로 감싸서 원래대로 되돌리고 "장착하지 못했어요"를 보여주게 했다.

그런데 `try/catch`가 **로그인이 풀렸을 때의 redirect까지 삼키지 않을까** 걱정이 됐다. 직접 세션을 지우고 장착을 눌러 봤더니, Next.js가 첫 화면으로 정상 이동시켰다. 걱정은 재현해서 확인해야 한다.

## 4. 휴대폰 전용 가상 조이스틱

- 브라우저가 `(pointer: coarse)` — 손가락이 주 입력인 기기 — 일 때만 만든다. 데스크톱에는 안 보인다.
- 화면 왼쪽 아래에 고정. 손잡이를 많이 밀수록 빠르게, 가운데 8px 안쪽은 멈춤.
- 조이스틱 밖을 탭하면 원래처럼 그곳으로 걸어간다. 두 손가락까지 인식한다.
- 조작 안내 문구도 기기에 맞게 바꿨다: Tailwind의 `pointer-coarse:` 변형으로 CSS만으로 처리.

Playwright로 휴대폰을 흉내 내고(`isMobile`, `hasTouch`) 조이스틱을 끌어서 캐릭터가 움직이는 걸 스크린샷으로 확인했다. **실제 휴대폰에서는 아직 못 해 봤다.**
